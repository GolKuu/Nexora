# Источники данных KASE — реестр проверенных эндпоинтов

**Дата проверки: 13 августа 2026.** Все запросы ниже выполнены реально, с
живого сайта. Ни один эндпоинт не выдуман и не восстановлен по памяти.

## Как эти эндпоинты были найдены

kase.kz — это Angular-приложение с server-side rendering. Каждая страница
содержит `<script id="ng-state" type="application/json">` — состояние
transfer state, в котором Angular сохраняет **URL и тело каждого HTTP-запроса**,
выполненного при рендеринге страницы.

Метод, который можно повторить:

```bash
curl -s https://kase.kz/ru/bonds/ -o page.html
python - <<'EOF'
import re, json
h = open('page.html', encoding='utf-8').read()
state = json.loads(re.search(r'<script id="ng-state"[^>]*>(.*?)</script>', h, re.S).group(1))
for key, entry in state.items():
    if isinstance(entry, dict) and 'u' in entry:
        print(entry.get('s'), entry.get('u'))   # HTTP-статус и URL
EOF
```

Так был получен список ниже. Никакого обхода защиты: это те же публичные
запросы, которые делает браузер обычного посетителя.

> **Важно про завершающий слэш.** Без него KASE отвечает `301` на слэш-форму.
> Клиенты, которые не переносят query string через редирект, теряют фильтры.
> Всегда обращайтесь к слэш-форме.

## PUBLIC — доступно без авторизации, используется в MVP

Общее для всех: `GET`, ответ `application/json`, авторизация **не требуется**,
базовый URL `https://kase.kz`.

### 2. Параметры выпуска — ключевой эндпоинт

| | |
|---|---|
| **Что это** | Полная карточка одной облигации |
| **Endpoint** | `/api/instruments/bonds/{TICKER}/` |
| **Поля** | Внутри `characteristics`: **`isin`**, **`cfi`**, **`coupon_rate`** (% годовых), `coupon_type_*`, `nominal_value_*`, `one_lot`, `registred_volume`, `issued_volume`, `market_volume`, `prev_coupon_start_date`, **`next_coupon_start_date`**, `next_coupon_fixation_date`, `maturity_start_date`, `maturity_end_date`, `excluded_at`, `is_index`, `indexation_method_*`, `quatation_system_*` («чистая цена»), `quatation_unit_*` («процент от номинала»), `registrar_*`, `coupon_description_*` (свободный текст с периодом обращения) |
| **Частота** | При добавлении выпуска; далее раз в неделю (меняется `next_coupon_*`) |
| **Ограничения** | Один запрос на выпуск. ~970 активных облигаций → синхронизация порциями с ограничением параллелизма |
| **MVP** | Да — без него нет ни ISIN, ни купона, ни графика выплат |

Проверенный пример (`BRKZb14`): `isin=KZ2C00004273`, `cfi=DBFUFR`,
`coupon_rate=11.0`, `nominal=1000.0`, `one_lot=1.0`,
`prev_coupon=2026-06-18`, `next_coupon=2026-12-18`, `maturity=2030-06-18`.

**Частота купона не публикуется.** Она выводится из разрыва между
`prev_coupon_start_date` и `next_coupon_start_date`: 6 месяцев → 2 раза в год.
Реализовано в `infer_coupon_frequency()`.

**CFI (ISO 10962) — единственный машиночитаемый источник** признаков
`secured` / `subordinated` / `callable` / `putable`. `DBFUFR` = долговая,
облигация, фиксированный купон, необеспеченная, фиксированное погашение,
именная. Разбор в `parse_cfi()`; нераспознанная позиция дает `None`, а не
`False`.

### 3. Итоги торгов — цены и доходности

| | |
|---|---|
| **Что это** | Результаты последней торговой сессии по облигациям |
| **Endpoint** | `/api/trade-results/bonds/` |
| **Ответ** | ~139 записей — только бумаги, по которым были заявки или сделки |
| **Поля** | `current_bid`, `current_offer` (**ask!**), `openprice`, `max_price`, `min_price`, `last_deal_price`, `avg_price`, `last_deal_date`, `dealcnt`, `vol`, `volkzt`, `volusd`, `dtm`, `basis` (база начисления, `360`), `board`, и зеркальные наборы `dirty_*` и `*_dohod` (доходности к bid/ask/last/avg) |
| **Частота** | Несколько раз в день; данные — итоги сессии, не поток реального времени |
| **MVP** | Да — именно этот эндпоинт делает возможным честное ценообразование |

> ### ⚠ Две разные шкалы в одном ответе
>
> Проверено на 22 выпусках: **`clean`-поля — процент от номинала, а все
> `dirty_*` поля — деньги за одну бумагу в валюте выпуска.**
>
> Пример `BRKZb14`: `last_deal_price = 88.5775` (% от номинала),
> `dirty_last_price = 902.58` (тенге при номинале 1 000).
>
> НКД = `dirty_money − clean_pct/100 × nominal` = 16.81 ₸ = 1.68 % номинала.
>
> Смешать шкалы = ошибиться в цене в ~10 раз. `KasePublicApiProvider.get_quotes()`
> приводит все к проценту от номинала и **требует номинал**; без него
> `dirty_price` и `accrued_interest` возвращаются как `null`, а не в неверной шкале.

Доходности (`*_dohod`) публикуются в процентах годовых и переводятся в
десятичную дробь при сохранении.

### 6. Финансовая отчетность

| | |
|---|---|
| **Endpoint** | `/api/companies/fin-data/{CODE}/` |
| **Ответ** | Поквартальный ряд; для `BRKZ` — 99 периодов |
| **Поля** | `change_date`, `units` (`thnd` — тысячи!), `currency`, `net_profit`, `gross_income`, `own_capital`, `volume_sale`, `aggregate_assets`, `total_liabilities`, `authorized_capital`, `audited`, `roe`, `roa`, `ros` |
| **Частота** | После публикаций отчетности (ежеквартально) |
| **MVP** | Да, с оговоркой ниже |

> **Ограничение, определяющее модель Credit Score.** В этом источнике **нет**
> EBITDA, процентных расходов, разбивки долга и денежных потоков. Поэтому
> **Debt/EBITDA, Net Debt/EBITDA и Interest Coverage из публичных данных KASE
> не вычисляются** — они остаются `null`, и `confidence` кредитной оценки
> понижается. Доступны: leverage как «обязательства / капитал»,
> equity/assets, ROA, ROE, ROS, динамика выручки и прибыли, факт аудита.
>
> Мы сознательно **не** подставляем `total_liabilities` вместо `total_debt`:
> обязательства включают кредиторскую задолженность, а у банков — депозиты
> клиентов. В модели это отдельная колонка `financial_statements.total_liabilities`.

## LICENSED / API — требует договора

| Источник | Статус |
|---|---|
| Контрактный API KASE (`KASE_API_URL` + `KASE_API_KEY`) | Реализован как `KaseApiProvider`. Карты `ENDPOINTS` и `FIELD_MAP` — заготовка под ваш договор, **не документированный контракт биржи**. Требует заключения договора с KASE |
| Поток котировок в реальном времени | Публичный API отдает **итоги сессии**, не тик-поток. Реальное время — только по договору |
| Глубина стакана (order book depth) | Публично не публикуется. Доступны только лучшие bid/ask |

**Ничего из этого не обходится.** Точка подключения оставлена
(`KASE_DATA_MODE=official_api`), фиктивных эндпоинтов не создано.

## NOT AVAILABLE — публично отсутствует

| Данные | Что делаем |
|---|---|
| **График купонных выплат** отдельным эндпоинтом | **Восстанавливаем** из `coupon_rate`, `prev/next_coupon_start_date`, `maturity_start_date` и номинала. Каждый расчетный поток помечен `is_estimated` |
| **Кредитные рейтинги агентств** | `get_ratings()` возвращает `[]`. Рейтинг **никогда не выдумывается**; при его отсутствии снижается `confidence` кредитной оценки |
| **Тиковый журнал сделок** | Доступен только агрегат сессии (VWAP + число сделок). Возвращается как одна агрегированная запись, а не как отдельные сделки |
| **Глубина заявок** | Нет. Поэтому большие суммы получают `liquidity_warning`, а не выдуманную цену исполнения |
| **EBITDA, процентные расходы, денежные потоки** | Нет в `fin-data`. См. ограничение в разделе 6 |
| `robots.txt` | Отдает `404` — файла нет |

## Инфляция — официальный первичный источник

| | |
|---|---|
| **Издатель** | Бюро национальной статистики АСПР РК — `stat.gov.kz` |
| **Страница** | `/ru/industries/economy/prices/publications/` |
| **Бюллетень** | «Инфляция в Республике Казахстан (месяц год)» |
| **Проверенное значение** | **10.2 % годовых, июль 2026** ([публикация 509832](https://stat.gov.kz/ru/industries/economy/prices/publications/509832/)) |
| **Формат** | HTML + XLSX. **JSON API отсутствует** |
| **Частота** | Ежемесячно |

Реализация — `StatGovInflationCollector`: читает индекс публикаций, находит
свежий бюллетень по инфляции (`<a class="release-title">`), открывает его и
извлекает значение из формулировки «…составила 10,2 %».

Ограничения приняты осознанно:

* парсер привязан к верстке stat.gov.kz и сломается при редизайне — тогда он
  **падает явно и не трогает сохраненное значение**: устаревшее, но настоящее
  число лучше свежего выдуманного;
* значение вне диапазона 0–100 % годовых считается ошибкой разбора, а не новостью;
* ручное переопределение (`python scripts/kase.py set-inflation 10.2`) имеет
  приоритет и существует именно на случай поломки парсера.

Национальный банк РК дополнительно отдает официальные курсы валют:
`https://nationalbank.kz/rss/rates_all.xml` (проверено, `200`).

## Вежливость к источнику

* `asyncio.Semaphore` ограничивает параллелизм (по умолчанию 4 запроса);
* таймауты на каждом запросе, сетевая ошибка возвращается как данные, а не как падение;
* каталог и параметры выпусков синхронизируются по расписанию, а не по запросу пользователя;
* `ENRICH_BUDGET` ограничивает число карточек выпусков за один прогон.

## Аудит

Каждый ответ источника сохраняется в `raw_kase_data` целиком: URL, HTTP-статус,
content-type, тело, SHA-256 тела, длительность запроса, момент загрузки и
`data_mode`. Любое число на экране прослеживается до исходных байтов.
