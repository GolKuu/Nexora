# Архитектура

## Поток данных

```
KASE (API / сайт)  ──►  Provider  ──►  Collector  ──►  PostgreSQL
                          │                              │
                    raw_kase_data                        ▼
                                              MetricsService (расчеты)
                                                         │
                                              ScoringService (оценки)
                                                         │
                                                   API (FastAPI)
                                                         │
                                             ┌───────────┴───────────┐
                                        Frontend                  LLM
                                     (форматирование)      (только текст)
```

Ключевое свойство: путь числа от источника до экрана проходит только через
детерминированный код. LLM подключается сбоку и влияет исключительно на
формулировки.

## Слои бэкенда

| Слой | Ответственность | Что запрещено |
|---|---|---|
| `providers/` | общение с внешним миром | писать в БД |
| `collectors/` | перенос DTO в БД с провенансом | считать метрики |
| `repositories/` | запросы к БД | бизнес-логика |
| `calculations/` | чистая математика | БД, сеть, LLM |
| `scoring/` | превращение фактов в оценки | БД, сеть |
| `services/` | сборка ответа из слоёв выше | HTTP-детали |
| `api/` | HTTP, валидация, коды ошибок | расчеты |
| `ai/` | LLM-абстракция | производить числа |

## Модель данных (24 таблицы)

**Справочник:** `issuers`, `bonds`, `bond_cashflows`, `peer_groups`
**Рынок:** `bond_quotes`, `bond_trades`
**Отчетность:** `financial_statements`, `issuer_metrics`, `credit_ratings`
**Макро:** `yield_curves`, `inflation_data`, `fx_rates`
**Производное:** `bond_metrics`, `bond_scores`, `score_components`
**Пользователь:** `users`, `user_settings`, `portfolios`,
`portfolio_positions`, `watchlist`, `alerts`
**Служебное:** `ai_analyses`, `data_sources`, `raw_kase_data`

Используются только переносимые типы колонок (без `JSONB`/`UUID`), поэтому
одна и та же схема разворачивается и на PostgreSQL, и на SQLite в тестах.

### Провенанс

`SourceMixin` добавляет `source`, `source_identifier`, `source_url`,
`source_timestamp`, `fetched_at`. `ComputedMixin` добавляет
`formula_version`, `model_version`, `calculated_at`. Любое важное число несёт
одно из двух.

## Пользователь и идентичность

Без регистрации доступны: TOP, поиск, карточка выпуска, сравнение,
калькулятор, настройки (в рамках браузера).

Идентичность передаётся заголовками:

- `X-Anon-Token` — UUID, который браузер генерирует один раз; достаточно для
  сохранения настроек, портфеля и избранного;
- `X-User-Id` — заглушка для будущей полноценной аутентификации.

Полноценная аутентификация (пароли, OAuth, сессии) **намеренно не
реализована** на этом этапе; это явно отмечено в `backend/app/api/deps.py`.
Публиковать write-эндпоинты в интернет до её появления нельзя.

## Кэш и фоновые задачи

Redis необязателен: при пустом `REDIS_URL` используется внутрипроцессный TTL-кэш
(`app/core/cache.py`), которого достаточно для одного воркера.

Планировщик (`app/jobs/scheduler.py`) — минимальный asyncio-цикл. Celery или
APScheduler будут оправданы, когда задач станет больше одной.

## Режим «Просто / Подробно»

Бэкенд отдаёт оба представления в одном ответе `GET /bonds/{id}`:

- `simple` — семь понятий: доходность, после инфляции, срок, надежность,
  ликвидность, потенциал, общая оценка;
- `pro` — YTM, clean/dirty price, НКД, duration, modified duration, convexity,
  кредитный спред, bid/ask, объемы.

Фронтенд переключает отображение, но никогда не пересчитывает: обе версии —
одни и те же числа, показанные с разной подробностью. По умолчанию — «Просто».
