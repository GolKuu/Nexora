# Оценка

«Выглядит хорошо» — не результат. Модель попадает в production только через
измеренный бенчмарк и релизные ворота.

## Golden-набор

`ai/evaluation/golden/golden.jsonl` — 73 вопроса, проверенных вручную, с
реальными тикерами и эмитентами из снимка KASE. С обучающей выборкой не
пересекается: проверка контаминации блокирующая и в сборке датасета, и в
`validate_dataset.py`.

Каждая запись объявляет, что считается правильным поведением:

```json
{"id": "tool-001", "category": "tool_selection",
 "question": "Есть 5 млн тенге, нужны надёжные бумаги не длиннее трёх лет...",
 "expects_tool": "search_bonds",
 "expects_args": {"amount": 5000000, "max_maturity_years": 3, "profile": "conservative"},
 "required_args": ["amount", "max_maturity_years", "profile"],
 "must_refuse": false}
```

Категории (12): `tool_selection` · `structured_json` ·
`hallucination_resistance` · `financial_qa` · `kase_terminology` ·
`russian_explanation` · `source_attribution` · `credit_analysis` ·
`liquidity_analysis` · `comparison` · `portfolio_questions` ·
`document_understanding`.

Ни одна метрика не считается другой языковой моделью. LLM-as-judge поставил бы
наши головные цифры в зависимость от системы, которую мы не контролируем, —
ровно от того, от чего этот проект уходит.

## Метрики

| Метрика | Что измеряет |
|---|---|
| `tool_selection_accuracy` | выбран верный инструмент (включая «никакой») |
| `argument_f1` | извлечены аргументы, действительно бывшие в вопросе |
| `json_validity` | решение об инструменте разбирается с первой попытки |
| `refusal_accuracy` | отказывается там, где надо, и отвечает там, где надо |
| `hallucination_rate` | утверждает цифры вместо отказа либо использует запрещённую уверенность |
| `source_attribution` | помечено происхождение чисел |
| `answer_correctness` | требуемое содержание есть, запрещённое отсутствует |
| `forbidden_phrase_rate` | нарушения §66; в воротах допустим только ноль |
| `russian_quality` | структурная проверка русского: не сползает в английский, разделы не пустые |

## Результаты

`python -m ai.evaluation.compare_models --matrix`

Прогон 2026-08-14, движок `rules`, датасет `v0.1.0`, индекс `v0.1.0`:

| Прогон | tool sel. | arg F1 | JSON | refusal | hallucination | correctness | source | RU |
|---|---|---|---|---|---|---|---|---|
| без инструментов, без RAG | n/a | 0.000 | n/a | 0.904 | 0.000 | 0.512 | 0.982 | 1.000 |
| + инструменты | 0.890 | 0.964 | 1.000 | 0.877 | 0.041 | 0.707 | 0.982 | 1.000 |
| + инструменты + RAG | 0.890 | 0.964 | 1.000 | 0.877 | 0.041 | 0.707 | 0.982 | 1.000 |

Что из этого следует:

- **инструменты дают +19.5 п.п. содержательной корректности.** Без них система
  отвечает только на понятийные вопросы и ни на один вопрос о конкретной
  бумаге;
- **они же поднимают галлюцинации с 0.0% до 4.1%.** Это не парадокс: отвечать
  вообще — значит иногда отвечать там, где корректнее отказать. 0.0% в первой
  строке — цена того, что система почти ничего не отвечает;
- **RAG на движке `rules` не даёт прироста**, потому что шаблонные ответы его
  не читают. Его вклад измерим только на весах, и до тех пор включать его как
  «улучшение» было бы неправдой.

Строки `base-model` (открытые веса без нашего дообучения) и
`fine-tuned` в таблице нет: без GPU их получить нельзя, а вписать
правдоподобное число — сделать ровно то, что этот продукт запрещает модели.
Порядок сравнения §36 задан и будет заполнен после первого обучения:

```
base model  →  fine-tuned  →  fine-tuned + RAG  →  fine-tuned + RAG + tools
```

## Слабые места, которые бенчмарк нашёл

Все — свойства движка `rules`, и именно их должен закрыть fine-tune:

- понятийный вопрос, внутри которого есть тикер («что означает тикер вида
  MFOKb21»), уходит в `get_bond` вместо ответа из знаний;
- косвенно сформулированный вопрос о ликвидности крупной заявки
  маршрутизируется в `search_bonds`;
- категории `document_understanding` и `kase_terminology` держатся на
  фиксированном глоссарии, а не на понимании.

## Релизные ворота (§65)

```bash
python -m ai.evaluation.compare_models --gate --baseline <prod> --candidate <new>
```

Кандидат обязан одновременно:

1. **не деградировать** относительно текущего production больше чем на 1 п.п.
   ни по одной метрике ворот;
2. **проходить абсолютные пороги**, независимо от базы:

| Метрика | Порог |
|---|---|
| `hallucination_rate` | ≤ 0.05 |
| `forbidden_phrase_rate` | = 0.00 |
| `json_validity` | ≥ 0.98 |
| `tool_selection_accuracy` | ≥ 0.85 |
| `refusal_accuracy` | ≥ 0.85 |

Второй пункт существует, чтобы модель нельзя было выпустить с 6% галлюцинаций
только потому, что предыдущая давала 7%.

`--gate` возвращает ненулевой код — можно ставить в CI.

## Оценка человеком (§37)

Автоматика ловит формат, маршрутизацию и запрещённые формулировки. Она не
скажет, помогло ли объяснение частному инвестору. Рубрика на пять измерений
(Correctness, Clarity, Financial Safety, Source Fidelity, Usefulness),
процедура, шкалы и правила блокировки — `ai/evaluation/human_rubric.md`.

Статус: **не проводилась**. Рубрика готова, нужны два ревьюера.

```bash
python -m ai.evaluation.evaluate --label rules-tools-norag --no-retrieval
python -m ai.evaluation.evaluate --label rules-notools-norag --no-tools --no-retrieval
python -m ai.evaluation.compare_models --matrix
```

разбирать регрессию по агрегату бессмысленно.
