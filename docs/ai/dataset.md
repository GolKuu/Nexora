# Датасет

## Устройство

```
data/ai/
  raw/<version>/          как получено
  normalized/<version>/   очищенные документы (domain.jsonl)
  chunks/<version>/       чанки для retrieval
  sft/<version>/          train.jsonl, dev.jsonl, quality.txt, manifest.json
  preference/<version>/   пары предпочтений (P1)
  evaluation/<version>/   отложенный материал
```

Директория версии неизменяема. Другие входные данные — другая версия. В
`manifest.json` записаны источники, время съёмки снимка, версии промптов и
формул, git-коммит, распределения и хеши файлов.

Сборка:

```bash
python -m ai.datasets.build --version v0.1.0 --today 2026-08-14
```

`--today` фиксирует «сегодня»: без него пересборка через месяц даст другие
сроки до погашения и другой датасет при том же снимке.

## Provenance

Обязательные поля каждого примера (§7):

```json
{
  "source": "kase_public_api",
  "source_url": "https://kase.kz/api/instruments/bonds/MFRFb27/",
  "document_id": "bond:MFRFb27",
  "document_date": "2026-08-13",
  "collected_at": "2026-08-13T11:16:51+00:00",
  "license_status": "public",
  "language": "ru",
  "dataset_version": "v0.1.0"
}
```

`license_status: public` без `source_url` не проходит валидацию: публичный
источник обязан быть предъявляемым.

## Очистка

`ai/datasets/cleaning.py`, по порядку: снятие HTML → нормализация кодировки
(включая типичный для скрейпа KASE случай cp1251, прочитанного как latin-1) →
удаление навигации и футера → нормализация дат к ISO → нормализация валют
(«тенге», «₸», «тг» → `KZT`; пробелы разрядов и запятая-разделитель) →
редактирование PII → определение языка → оценка качества.

Документы с `quality < 0.35` и «битые» (доля букв ниже 25%, символы замены) не
попадают в корпус; количество отброшенного пишется в манифест.

Дедупликация — точная по нормализованному отпечатку и близкая по шинглам
(Jaccard ≥ 0.85). Важная деталь: **к структурным документам она не
применяется**. Карточки выпусков и таблицы отчётности почти совпадают по
формулировкам и отличаются только числами — то есть ровно тем, что и является
содержанием. Прогон дедупликации по ним схлопывал 143 выпуска в горстку и
молча оставлял индекс без большинства тикеров.

## Разбор документов

HTML, PDF, XLSX/XLS, DOCX, TXT, JSON, CSV (`ai/datasets/parsing.py`).

Финансовые таблицы не превращаются в плоский текст. Они извлекаются
структурно (`Table`), отдаются чанкеру как таблицы и рендерятся выровненным
Markdown с сохранённой строкой заголовка. Баланс, размазанный в поток чисел,
учит модель, что «итого активы» и `3 698 502 257` не связаны.

Опциональные парсеры (`pypdf`, `openpyxl`, `python-docx`) импортируются лениво:
отсутствующий парсер делает формат неподдерживаемым с внятным сообщением, а не
роняет сборку.

## Чанкование

Не «каждые 500 символов». Границы — реальные: заголовок раздела, маркер
отчётного периода, разрыв страницы, начало таблицы. Таблица не режется, пока
помещается в `max_table_tokens`; не помещающаяся делится по строкам с
повторением заголовка. Мелкие соседние блоки одного раздела склеиваются.

Метаданные каждого чанка (§27): `issuer_code`, `bond_ticker`, `isin`,
`document_type`, `period`, `publication_date`, `source`, `source_url`, `page`,
`section`, `language`, `dataset_version`. Отсутствующее значение — `null`, а не
пропущенный ключ: «не знаем» и «не относится» не должны выглядеть одинаково.

## Типы обучения

**A. Доменная адаптация** — `data/ai/normalized/<version>/domain.jsonl`.
Карточки выпусков, развёрнутые в связный русский текст, таблицы отчётности,
макро-контекст, методические документы. Учит языку облигаций KASE.

**B. Instruction tuning** — `data/ai/sft/<version>/`. Выполнение задач
пользователя.

**C. Structured output** — задача `tool_call`: цель ответа — валидный JSON.

**D. Объяснение** — пары «профессионально → просто» и объяснения показателей
простым русским.

## Пример SFT

Вход: «У меня есть 5 млн тенге. Найди надежные облигации KASE до трех лет».

Цель обучения — **вызов инструмента**, а не список бумаг:

```json
{"tool": "search_bonds", "arguments": {
  "currency": "KZT", "max_maturity_years": 3, "profile": "conservative",
  "amount": 5000000, "min_credit_score": 70, "limit": 5}}
```

Список выпусков модель не придумывает — его возвращает инструмент. Следующий
ход обучает изложить результат по скелету «Коротко / Почему / Основные риски /
Что будет с X ₸ / Что проверить».

## Отказы

30 примеров, где правильный ответ — «недостаточно данных» (§17): несуществующий
выпуск, цена на произвольную прошлую дату, отсутствующая отчётность,
гарантированная будущая стоимость, числовая вероятность дефолта, купон «по
аналогии», внедрённая в документ инструкция, вопрос «покупать или нет».

Отказы конкретны: говорят, чего именно нет и что ответило бы на вопрос.
Отказ, звучащий как отписка, — тоже дефект.

Отдельно: маршрутизатор обучен отвечать `{"tool": null, "reason": ...}` —
«ни один инструмент не подходит» должно быть выразимо.

## Разметка происхождения чисел

Каждое число в обучающих ответах помечено (§18):

- «YTM 22.7% — данные KASE» → ФАКТ;
- «реальная доходность 11.3% — расчет системы» → РАСЧЕТ;
- «в плохом сценарии прибыль 1.2 млн ₸ — сценарий» → СЦЕНАРИЙ;
- «эмитент выглядит устойчивым — AI-интерпретация» → ИНТЕРПРЕТАЦИЯ.

## Синтетика

93.4% примеров сгенерированы программно из проверенных структурированных
данных и помечены `synthetic=true`. Это разрешено (§58) и эффективно, но с
двумя обязательствами:

1. синтетический ответ не выдаётся за источник — происхождение хранится;
2. **все числа получены нашим калькулятором** (§59). Строка «5 млн ₸ → 4934
   облигации» приходит из `calculate_investment`, а не из головы автора
   шаблона.

Второе проверяется: `validate_dataset.py` заново вычисляет выборку записанных
значений тем же инструментом, который их произвёл, и сообщает расхождения.
Сравнение ведётся с тем же инструментом намеренно: опубликованный KASE YTM и
наш `calculate_ytm` законно расходятся из-за конвенций расчёта, и сравнение
одного с другим давало бы «дрейф» на каждом примере.

Написанное человеком (глоссарий, отказы, интерпретация коэффициентов, вопросы
о портфеле) помечено `synthetic=false` — 6.6%.

## Проверки качества

`ai/datasets/quality.py`, отчёт в `quality.txt` / `quality.json`:

дубликаты (точные и близкие) · пустые примеры · битый JSON в целях
`tool_call` · слишком длинные · распределения по задачам, языкам и источникам ·
доля синтетики · **пересечение train с golden-набором**.

Блокирующие проблемы останавливают сборку и обучение. Пересечение с golden —
блокирующее: обучение на бенчмарке обесценивает все последующие числа.

`v0.1.0`: точные дубликаты 0.2%, близкие 5.5%, битый JSON 0, пересечений с
golden 0, замечаний нет.

## Разбиение

Стратифицировано по задачам, группировка по хешу промпта — перефразированный
до идентичности вопрос не может оказаться по обе стороны. Каждая задача
представлена и в train, и в dev. Утечка проверяется явно.

## Версионирование

Версии, от которых зависит воспроизводимость ответа: датасет, модель, промпты,
формулы расчёта, скоринг, retrieval-индекс. Все шесть записаны в
`models/<version>/metadata.json`.
