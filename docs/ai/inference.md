# Инференс

## Запуск

```bash
pip install -r ai/requirements.txt
uvicorn ai.inference.server:app --host 0.0.0.0 --port 8100
curl http://localhost:8100/health
```

Работает сразу, без GPU и без весов: рантайм по умолчанию — `rules`.

## Рантаймы

`runtime` в `ai/configs/inference.yaml` (или `KASE_AI_RUNTIME`):

| Рантайм | Что это | Когда |
|---|---|---|
| `rules` | детерминированный русский маршрутизатор + шаблонные ответы, без весов | CI, офлайн-тесты, пол в бенчмарке, работа без GPU |
| `vllm` | наши веса на нашей GPU | production |
| `llama_cpp` | наши веса в GGUF на CPU | CPU-развёртывание |
| `transformers` | один процесс, `generate` | дев-машина с GPU |

`vllm` и `llama_cpp` говорят по протоколу OpenAI — это формат совместимости,
который оба рантайма реализуют, а не обращение к вендору. `base_url`
проверяется на локальность: попытка указать удалённый вендорский эндпоинт
отклоняется исключением, а не принимается молча.

```bash
# production
vllm serve models/kase-ai-8b-v0.1/merged --served-model-name kase-ai-8b-v0.1
KASE_AI_RUNTIME=vllm uvicorn ai.inference.server:app --port 8100

# CPU
llama-server -m models/kase-ai-8b-v0.1/gguf/kase-ai-8b-Q4_K_M.gguf -c 8192
KASE_AI_RUNTIME=llama_cpp uvicorn ai.inference.server:app --port 8100
```

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | что загружено, какая версия отвечает, сколько чанков в индексе |
| POST | `/ai/chat` | полный цикл; `"stream": true` — SSE |
| POST | `/ai/tool-decision` | только инструмент и аргументы, строгий JSON |
| POST | `/ai/explain` | переизложить детерминированное объяснение оценки |
| POST | `/ai/analyze-document` | разобрать документ как данные, а не инструкции |
| POST | `/ai/tool` | исполнить проверенный вызов инструмента (тот же путь, что у агента; тоже только чтение) |
| POST | `/ai/feedback` | «полезно / не полезно» → очередь на ревью человеком |

```bash
curl -s localhost:8100/ai/chat -H 'Content-Type: application/json' \
  -d '{"message":"У меня 5 млн тенге, найди надёжные бумаги до трёх лет","profile":"conservative"}'

curl -N localhost:8100/ai/chat -H 'Content-Type: application/json' \
  -d '{"message":"Что будет, если вложить 3 млн ₸ в CLSGb8?","stream":true}'
```

## Стриминг (§39)

SSE-события: `tool_decision` → `tool_result` → `retrieval` → серия `delta` →
`done`. Решение об инструменте и его исполнение происходят **до** первого
токена, поэтому пользователь видит, чем система пользуется, а не смотрит в
пустой экран.

Проверка безопасности выполняется на накопленном тексте в конце. Нарушение
даёт событие `replace` с безопасным ответом: заявление о гарантированной
доходности не должно остаться на экране только потому, что оно уже вытекло
токенами.

## Цикл ответа

```
вопрос
  → проверка на внедрённые инструкции
  → retrieval (фильтр по тикеру/ISIN → векторный поиск → опционально reranker)
  → решение об инструменте (модель, температура 0, строгий JSON)
  → исполнение инструмента (детерминированный движок, права только на чтение)
  → сборка контекста (бюджет токенов, вырезание секретов)
  → ответ (модель)
  → проверка ответа (запрещённые формулировки, утечки)
```

Когда модель не уверена, она **не обращается к чужому API** (§61). Варианты:
уточнить, поискать ещё, вызвать инструмент, ответить «недостаточно данных».
Последнее — корректный исход, а не сбой.

Если инструмент сообщил `missing`, цикл сразу переходит к честному отказу, а
не отдаёт модели пустую нагрузку в надежде, что она справится.

## Разделение уровней (§45)

Системные правила, вопрос пользователя, результаты инструментов и найденные
документы — четыре разных уровня, а не одна склеенная строка. Контекст
приходит отдельным сообщением в размеченном блоке `<context>`, документы — в
`<retrieved_documents>` с источником у каждого, результаты инструментов — в
`<tool_result>`.

Строка «игнорируй предыдущие инструкции» внутри документа детектируется, не
выполняется, из текста **не вырезается** (иначе пользователь о ней не узнает)
и упоминается в ответе.

## Права (§46)

AI может: читать данные, запрашивать расчёты, сравнивать, объяснять.

AI не может: покупать, продавать, изменять рыночные данные, редактировать
исходные значения, выполнять произвольные запросы. Это не настройка — таких
инструментов не существует в реестре, а политика прав отклоняет их по имени
ещё до диспетчеризации.

## Секреты (§44)

В контекст не попадают пароли БД, ключи API, внутренние секреты и токены
аутентификации. Вырезание идёт по имени ключа (подстрокой: `password`,
`token`, `api_key`, `dsn`, …) и по форме значения (строка подключения,
`sk-…`, `Bearer …`). Вырезанные ключи попадают в трейс — молчаливой потери
данных не происходит.

## Память и персонализация (§47, §48)

История чата не используется как неконтролируемая база. Отдельно хранятся
структурированные настройки: профиль риска, базовая валюта, учёт инфляции,
режим отображения. В контекст из них пропускаются только эти четыре поля.

Профиль влияет на подачу и на подбор. Рыночные данные он не меняет: цена и
доходность одинаковы для осторожного и для агрессивного пользователя.

## Формат ответа (§49)

```
## Коротко
## Почему
## Основные риски
## Что будет с X ₸      (только если названа сумма)
## Что проверить
```

Раздел без данных пропускается целиком. Длинная аналитическая статья без
запроса не выдаётся.

## Наблюдаемость (§62)

`var/ai-logs/inference-<дата>.jsonl`: версия модели, версия промптов, движок,
латентность, токены, вызванные инструменты, идентификаторы найденных чанков,
ошибки, флаги безопасности, сигналы уверенности.

Вопрос и ответ по умолчанию **не логируются**: транскрипт облигационного
ассистента — это запись о чьих-то финансах. `log_payloads: true` включается
для разбора конкретного инцидента, и тогда полезная нагрузка проходит через то
же вырезание секретов.

«Сигналы уверенности» названы так намеренно: калиброванной вероятности у
системы нет, и называть их score значило бы изобразить ту самую ложную
точность, которую продукт запрещает в остальном.

## Профили оборудования (§54)

| Профиль | Рантайм | VRAM / RAM | Квантизация | Контекст | Конкурентность |
|---|---|---|---|---|---|
| Разработка / CI | `rules` | 2 ГБ RAM | — | — | не ограничена |
| Одна GPU | `transformers` / `vllm` | 24 ГБ VRAM | AWQ 4-bit | 16k | 4–8 (не измерено) |
| Production GPU | `vllm` | 24–48 ГБ VRAM | AWQ 4-bit | 16k | 8 (не измерено) |
| CPU fallback | `llama_cpp` | 16 ГБ RAM | GGUF Q4_K_M | 8k | 1–2 (не измерено) |

Пометка «не измерено» стоит там, где замера не было. Придумывать бенчмарк
запрещено (§54); цифры появятся после первого развёртывания на GPU.

Измеренное: движок `rules` — 2.1 мс на вопрос в среднем на 73 вопросах
golden-набора (CPU, без GPU).

## Офлайн (§53)

Базовые AI-функции работают внутри нашей инфраструктуры без обращения к
внешней LLM-службе. Интернет нужен для обновления данных KASE, но не для
инференса. Датасет, retrieval, бенчмарк и `runtime: rules` работают на снимке
без сети вообще.

## Связь с backend (§40)

```
Frontend → KASE Bond Backend → http://127.0.0.1:8100
```

`AI_PROVIDER=local` — по умолчанию. `external` существует только для
сравнительного прогона и пишет предупреждение в лог. Недоступность сервиса
инференса деградирует AI-функции к детерминированным объяснениям движка — так
же, как при отсутствии модели раньше.

## Live-данные KASE

При `KASE_AI_DATA_MODE=live` инструменты модели сами обновляют справочные
данные, котировки, графики выплат и отчетность через публичный JSON API
официального `https://kase.kz`. Хост жестко ограничен в коде, доступ только на
чтение, API-ключ и платный сервис не нужны. Результаты кешируются на
`KASE_AI_LIVE_TTL_SECONDS`; если KASE временно недоступен, используется
версионированный snapshot с его исходной датой и provenance.
