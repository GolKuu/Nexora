# Архитектура собственного ИИ

Главный принцип продукта — «вся сложность внутри системы» — здесь получает
буквальное продолжение: **интеллект продукта тоже внутри**. Мы владеем
датасетом, обучением, весами, промптами, инструментами, retrieval и
инференсом. Закрытый внешний LLM API не участвует в ответе ни на одном шаге и
не является резервным вариантом.

Что запрещено конструкцией:

```
Пользователь → чужой API → Ответ
```

Что построено:

```
KASE / документы / отчётность
        ↓  ai/tools/store.py, ai/datasets/parsing.py
   Сбор данных
        ↓  ai/datasets/cleaning.py
   Очистка
        ↓
   Нормализация
        ↓  ai/datasets/builders/*
   Сборка датасета
        ↓  data/ai/sft/<version>/
   Training Dataset
        ↓  ai/configs/base_models.yaml
   Open-weights base model  (Qwen3-8B, Apache-2.0)
        ↓  ai/training/train_lora.py
   Domain SFT / LoRA
        ↓  (P1) preference training
        ↓  ai/evaluation/
   Evaluation + release gate
        ↓  models/<version>/, ai/training/registry.py
   Model Registry
        ↓  ai/inference/server.py
   Inference Server
        ↓  ai/retrieval/, ai/tools/
   Retrieval + Tools
        ↓
   KASE Bond AI
```

## 1. Что здесь «своё»

| Компонент | Наш | Где |
|---|---|---|
| Датасет | да | `data/ai/`, `ai/datasets/` |
| Код обучения | да | `ai/training/` |
| Веса финальной модели | да (LoRA поверх открытой базы) | `models/` |
| Промпты и шаблоны | да | `ai/prompts/` |
| Каталог инструментов | да | `ai/tools/registry.py` |
| Retrieval и индекс | да | `ai/retrieval/`, `data/ai/index/` |
| Инференс | да | `ai/inference/` |
| Поведение и безопасность | да | `ai/inference/safety.py` |
| Базовые веса | открытые, Apache-2.0 | Qwen3-8B |
| Эмбеддинги | открытые, MIT | multilingual-e5-large |

Базовая модель заменяема: она задана в конфиге обучения, и переход на другую
семью — это правка `model.base` плюс проверка, что шаблон чата совпадает
(проверяется автоматически в `prepare_dataset.assert_template_agreement`).

## 2. Выбор базовой модели

Обучать многомиллиардную модель с нуля бессмысленно: у нас нет ни корпуса, ни
бюджета, а нужны нам не общие языковые способности, а узкая специализация.
Правильный путь — качественная открытая база плюс наше доменное обучение.

Рассмотренные размеры:

| Размер | Обучение | Инференс | Вывод |
|---|---|---|---|
| 3–4B | ~10 ГБ VRAM (QLoRA) | быстрый, идёт на CPU | держит формат JSON, но заметно слабее в русских объяснениях и в многошаговых рассуждениях о кредитном качестве |
| **7–8B** | **~20 ГБ VRAM (QLoRA)** | **~1 карта 24 ГБ в AWQ** | **баланс: устойчивый русский, надёжный tool calling, приемлемая латентность** |
| 14B | ~40 ГБ VRAM | 48 ГБ или 2×24 | лучше в анализе отчётности; для MVP избыточно |
| 32B+ | многокарточное | дорого | не окупается на нашей задаче |

Выбор для первого production MVP — **Qwen/Qwen3-8B**:

- **лицензия** — Apache-2.0; это первый фильтр, а не последний. Llama-3.1 и
  Gemma-3 отклонены именно здесь: их лицензии тянут за собой политику
  допустимого использования, привязанную к весам финансового продукта;
- **русский** — нативный мультиязычный претрейн, а не машинный перевод; в
  финансовом регистре читается естественно;
- **tool calling** — штатный chat-template с ролью инструмента, поэтому наш
  формат `{"tool": ..., "arguments": {...}}` не приходится «прививать» против
  шаблона;
- **structured output** — держит JSON под русским промптом, а с
  `response_format: json_object` в vLLM разбирается с первой попытки;
- **VRAM** — QLoRA r=32 при 4096 токенах помещается в 24 ГБ; тот же класс
  карты обслуживает инференс;
- **заменяемость** — 4B и 14B той же семьи используют тот же токенизатор и
  шаблон, так что переход вверх или вниз не трогает датасет.

Соперник, оставленный в бенчмарке, — `t-tech/T-lite-it-1.0` (Apache-2.0,
Qwen2.5-7B с продолженным претрейном на русском корпусе): его русский регистр
ближе к нашему домену, но tool-шаблон слабее. Полные записи, включая причины
отказов, — `ai/configs/base_models.yaml`.

## 3. Слои системы

### Инструменты — там, где числа

Модель не считает (§12). Двенадцать инструментов из
`ai/tools/registry.py` — единственный источник цифр, и за каждым стоит
`app.calculations` / `app.scoring`, то есть тот же движок, что рисует цифры в
интерфейсе. Один реестр читают все трое: генератор датасета, обучение и
сервер, поэтому «чему учили» и «что исполняется» не расходятся.

Аргументы типизированы, набор закрыт, произвольного SQL нет и не будет.
Инструментов записи не существует: купить, продать или изменить рыночное
значение система не может в принципе (§46).

### Retrieval — там, где знания

Знания KASE не запихиваются в веса. Индекс строится из тех же нормализованных
документов, что и датасет, чанкование учитывает структуру (заголовки,
периоды, страницы, таблицы целиком), у каждого чанка есть метаданные для
фильтрации до ранжирования. Названный в вопросе тикер становится жёстким
фильтром: лучше вернуть пусто, чем отчётность чужого эмитента.

### Контекст — там, где дисциплина

`ai/retrieval/context_builder.py` отдаёт модели минимум: карточка выпуска,
последняя котировка, оценки, финансовые показатели, результат расчёта,
найденные документы — в пределах бюджета токенов. Секреты вырезаются по имени
ключа и по форме значения (§44); дамп базы в промпт не попадает.

### Безопасность — там, где данные притворяются инструкциями

Документы, результаты инструментов и наблюдения браузера приходят
размеченными блоками. Строка «игнорируй предыдущие инструкции» внутри
документа детектируется, не выполняется и при необходимости упоминается в
ответе. Системные правила, результаты инструментов, найденные документы и
вопрос пользователя — четыре разных уровня, а не одна склеенная строка (§45).

## 4. Инференс

`ai/inference/engine.py` даёт четыре рантайма за одним интерфейсом:

- `vllm` — наши веса на нашей GPU;
- `llama_cpp` — наши веса в GGUF на CPU;
- `transformers` — один процесс, для дев-машины;
- `rules` — без весов: детерминированный русский маршрутизатор и шаблонные
  ответы.

`rules` существует по трём причинам, и ни одна из них не «заглушка»: система
должна работать и проверяться до появления весов; это измеренный пол в
бенчмарке, благодаря которому «дообучение помогло» — число, а не заявление; и
это то, чем продукт отвечает, когда GPU недоступна. Обращения к чужому API в
этом случае не происходит (§61).

Для `vllm` и `llama_cpp` протокол OpenAI используется как формат
совместимости — оба рантайма его реализуют. `base_url` проверяется на
локальность: попытка указать удалённый вендорский эндпоинт отклоняется с
ошибкой, а не молча принимается.

## 5. Как это связано с backend

```
Frontend → KASE Bond Backend → http://127.0.0.1:8100  (ai/inference/server.py)
```

`AI_PROVIDER=local` — режим по умолчанию. `external` существует только для
сравнительного прогона (§36) и пишет предупреждение в лог. Если сервис
инференса недоступен, AI-функции деградируют к детерминированным объяснениям
движка — так же, как это было всегда при отсутствии модели.

## 6. Приоритеты

**P0 (сделано):** открытая база выбрана и обоснована; пайплайн датасета;
инструкционный датасет KASE; tool calling; RAG; русские объяснения; бенчмарк
галлюцинаций; локальный инференс.

**P0 (осталось):** запуск fine-tuning на GPU и строка `base-model` в
бенчмарке.

**P1:** дообучение на финансовых документах; reranker (после замера);
специализация на кредитном анализе; портфельная аналитика.

**P2:** vision-language модель; продолженный претрейн; модели крупнее 14B.
