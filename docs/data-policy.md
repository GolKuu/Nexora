# Политика работы с данными

Пять правил, которым подчинён весь код.

## 1. Нет данных — значит `NULL`

Ноль — это значение, а не синоним «неизвестно». Ни одна функция расчетного
движка не подставляет ноль вместо пропуска: при отсутствующем входе она
возвращает `None`, а колонка в БД остаётся `NULL`.

Практическое следствие: облигация без данных о ликвидности не получает
Liquidity Score 0 (что читалось бы как «продать невозможно») — компонент
исключается из расчета, а `confidence` снижается.

## 2. У каждого числа есть происхождение

| Источник | Поля |
|---|---|
| Внешние данные | `source`, `source_identifier`, `source_url`, `source_timestamp`, `fetched_at` |
| Производные величины | `formula_version`, `model_version`, `calculated_at` |

Полные ответы провайдеров сохраняются в `raw_kase_data` вместе с HTTP-статусом,
хэшем содержимого и длительностью запроса.

## 3. Демо-данные всегда видны как демо

- каждая строка помечена `data_mode = "mock"` и `source = "mock"`;
- `MockKaseProvider.is_mock == True`, health-probe прямо пишет, что KASE не
  подключен;
- фабрика провайдеров бросает `MockDataForbiddenError` при
  `APP_ENV=production`;
- `KaseCollector` отказывается писать демо-данные в продакшн-базу;
- `CompositeKaseProvider` логирует предупреждение при каждом ответе от
  демо-источника;
- API добавляет `warning`, фронтенд — баннер на каждой странице;
- Data Quality Score умножается на 0.5.

## 4. Критические расчеты — только на бэкенде

`frontend/utils/format.ts` умеет форматировать числа и ничего больше.
Проценты, доходности, реальный доход, оценки приходят готовыми. Единственное
преобразование на клиенте — доля → проценты для отображения
(`formatRate`), и оно не создаёт новой финансовой величины.

## 5. LLM не является калькулятором

Системный промпт (`app/ai/prompts.py`) прямо запрещает модели считать и
придумывать числа. Архитектурно это подкреплено тем, что модель получает уже
готовый объект объяснения и её ответ никуда, кроме поля `content` в
`ai_analyses`, не попадает.

Если модель недоступна, объяснение формирует
`app/scoring/explain.deterministic_text`, а ответ помечается
`generated_by: "engine"`. Отсутствие ключа LLM снижает удобство, но не
корректность.

## Что ещё не сделано

Честный список на текущем этапе:

- полноценная аутентификация (сейчас — `X-Anon-Token` и заглушка `X-User-Id`);
- парсинг PDF/XLS отчетности эмитентов с сайта KASE;
- селекторы `KaseWebsiteProvider` и карта полей `KaseApiProvider` требуют
  сверки с реальными источниками (см. `docs/kase-integration.md`);
- обработка alert'ов (модель и API-схема есть, доставка уведомлений — нет);
- мультивалютная переоценка портфеля через `fx_rates` (таблица есть, логика
  пересчета не подключена).
