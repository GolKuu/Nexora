# Подключение к KASE

Этот документ описывает, что в проекте **реализовано**, что **требует
настройки под конкретный контракт**, и как проверить, подключена ли биржа на
самом деле.

## Честная позиция проекта

- Проект **не содержит поддельного API KASE**.
- Ни один эндпоинт не сообщает «KASE подключен» на основании конфигурации:
  `/api/v1/health/kase` выполняет реальный сетевой запрос.
- Демо-данные никогда не выдаются за рыночные: они помечены
  `data_mode = "mock"`, а фабрика провайдеров отказывается их создавать при
  `APP_ENV=production`.

## Режимы (`KASE_DATA_MODE`)

| Режим                | Цепочка провайдеров                                 |
|----------------------|-----------------------------------------------------|
| `official_api`       | `KaseApiProvider`                                    |
| `browser`            | `KaseBrowserProvider` — настоящий браузер на публичном сайте |
| `website_structured` | `KaseWebsiteProvider` — чтение HTML по HTTP (псевдоним: `website`) |
| `auto`               | `KaseApiProvider` (если есть ключ) → `KaseBrowserProvider` → `KaseWebsiteProvider` → `MockKaseProvider` (только вне production) |
| `mock`               | `MockKaseProvider` (в production — ошибка запуска)   |

**`KASE_API_KEY` нужен только для `official_api`.** Всё, что публично видно
посетителю kase.kz, браузерный агент получает без ключа.

`CompositeKaseProvider` перебирает источники по порядку, запоминает, кто
ответил (`last_source`), и пишет предупреждение в лог при каждом ответе от
демо-провайдера.

## `KaseApiProvider` — контрактный API

**Реализовано полностью:** HTTP-клиент с bearer-авторизацией, таймауты,
разбор ответов, провенанс на каждом DTO, сохранение сырых payload'ов в
`raw_kase_data`, реальный health-probe, аккуратный парсинг чисел
(нераспознанное значение → `None`, никогда не `0`).

**Требует настройки под ваш контракт:** карта эндпоинтов `ENDPOINTS` и карта
полей `FIELD_MAP` в `backend/app/providers/kase_api.py`. Значения по умолчанию —
разумная заготовка, а не документированный контракт KASE.

Порядок подключения:

1. Заключите договор с KASE и получите ключ.
2. Заполните `KASE_API_KEY` и `KASE_API_URL`.
3. Приведите `ENDPOINTS` и `FIELD_MAP` в соответствие с документацией биржи.
4. Проверьте: `RUN_LIVE_KASE_TESTS=true pytest -m live_kase`.
5. Переключите `KASE_DATA_MODE=official_api`.

## `KaseBrowserProvider` — публичный сайт через браузер

Настоящий Chromium: сайт исполняет свой JavaScript, агент дожидается
отрисовки, переходит по вкладкам, читает таблицы и текст, находит ссылки на
документы. Каталог инструментов не захардкожен — он читается со страницы.

Проверено на живом сайте (август 2026): каталог
`/ru/markets/corporate-bonds`, страница выпуска
`/ru/investors/bonds/{TICKER}`, страница эмитента
`/ru/listing/issuers/{CODE}`.

Агент не обходит CAPTCHA, не логинится и не трогает ничего, кроме того, что
видит обычный посетитель. Подробности, ограничения и набор команд —
в [`docs/browser-agent.md`](browser-agent.md).

## `KaseWebsiteProvider` — публичный сайт

**Реализовано:** транспорт, сохранение сырого HTML, health-probe с подсчетом
распознанных строк, извлечение ссылок на документы эмитента.

**Требует проверки:** CSS-селекторы в `SELECTORS` и пути в `PATHS`
(`backend/app/providers/kase_website.py`). KASE меняет верстку без
предупреждения, поэтому селекторы вынесены в одно место и считаются
конфигурацией.

Если страница загрузилась, но ни одной строки распознать не удалось,
провайдер выбрасывает `UpstreamError` с понятным текстом — он не возвращает
пустой список молча и не подставляет выдуманные значения.

Перед включением убедитесь, что ваш сценарий использования соответствует
условиям использования сайта и `robots.txt`.

## Проверка подключения

```bash
python scripts/check_kase.py
# 0 — ответил реальный источник
# 1 — источник недоступен либо отдаются демо-данные
```

```bash
curl http://localhost:8000/api/v1/health/kase
```

Ответ содержит:

```jsonc
{
  "configured_mode": "mock",
  "provider": "mock_kase",
  "connected": false,        // true только при реальном ответе не-демо источника
  "is_mock": true,
  "checked_at": "…",
  "detail": "…",
  "warning": "ВНИМАНИЕ: обслуживаются демонстрационные данные…"
}
```

## Что сохраняется при каждой загрузке

| Поле                | Значение                                       |
|---------------------|------------------------------------------------|
| `source`            | имя провайдера (`kase_api`, `kase_website`, `mock`) |
| `source_identifier` | тикер или код эмитента                         |
| `source_url`        | конкретный URL ответа                          |
| `source_timestamp`  | момент, к которому относятся данные            |
| `fetched_at`        | момент запроса                                 |
| `data_mode`         | `live` / `delayed` / `end_of_day` / `cached` / `mock` |

Полные ответы источников складываются в таблицу `raw_kase_data` вместе с
HTTP-статусом, хэшем и длительностью запроса — любое число на экране можно
проследить до исходных байтов.
