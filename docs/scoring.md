# Система оценок

Все оценки — целые числа от 0 до 100. Для каждой сохраняются `value`,
`version`, `calculated_at`, `confidence` и список компонентов с весами, чтобы
экран «Почему такая оценка?» строился из тех же данных, что и само число.

## Виды оценок

| Оценка | Смысл |
|---|---|
| Investment | Общая объективная привлекательность |
| Credit | Качество эмитента: способность платить |
| Liquidity | Насколько легко купить и продать |
| Growth | Потенциал роста рыночной цены — **не обещание роста** |
| Income | Качество денежных выплат |
| Real Return | Привлекательность после инфляции |
| Risk / Reward | Доходность относительно принимаемого риска |
| Stability | Устойчивость цены и рейтинга |
| Exit | Реалистичность выхода до погашения |
| Relative Value | Выгода относительно похожих выпусков |
| Data Quality | Полнота и свежесть исходных данных |
| Analysis Confidence | Насколько можно доверять оценке при таких данных |
| Hold | Насколько интересно держать до погашения |
| Trade | Насколько интересно выйти раньше |
| Personal | Персональная оценка пользователя |

**Personal Score никогда не изменяет базовые оценки.** Он хранится с
`user_id`, а базовые — с `user_id IS NULL`, и в выборках эти множества не
пересекаются.

## Investment Score

Складывается из семи компонентов (веса версии 1.0.0, профиль `balanced`):

| Компонент | Вес |
|---|---|
| Credit Quality | 0.26 |
| Risk / Reward | 0.18 |
| Real Return | 0.18 |
| Relative Value | 0.14 |
| Liquidity | 0.12 |
| Growth | 0.07 |
| Data Quality | 0.05 |

Профиль риска (`conservative` / `balanced` / `aggressive`) меняет **только**
эти веса. Подоценки остаются объективными: осторожный инвестор и агрессивный
видят одинаковый Credit Score, но разный Investment Score.

Все веса хранятся на бэкенде (`backend/app/scoring/weights.py`) и отдаются
через `GET /api/v1/meta/scoring-model`. Во фронтенде их копии нет.

## Кредитная модель: две разные

Банк — не маленькая промышленная компания. Debt/EBITDA для банка не имеет
смысла, поэтому применяются две независимые модели, выбор — по
`is_financial_institution` / `sector`.

**Корпоративная:** Net Debt/EBITDA, покрытие процентов, текущая и быстрая
ликвидность, операционный и свободный денежный поток, ROA/ROE/EBITDA-маржа,
Debt/Equity, динамика выручки и прибыли.

**Банковская:** достаточность капитала и Tier-1, NPL и покрытие резервами,
ликвидные активы и loan-to-deposit, ROA/ROE/чистая процентная маржа,
cost-to-income, доля капитала в активах.

Сверху накладываются структурные поправки: субординированный выпуск снижает
оценку, обеспечение и государственное участие — повышают (множитель ограничен
сверху 1.10).

## Отсутствующие данные

Недоступный компонент **исключается**, а веса оставшихся перенормируются.
Пропуск не превращается в ноль, потому что ноль читается как «очень плохо», а
не как «неизвестно». Доля фактически доступного веса возвращается как
`confidence`, а список пропущенных компонентов — в `missing_data`.

Если данные помечены как демонстрационные, Data Quality Score умножается
на 0.5 и в `notes` появляется явное предупреждение.

## Объяснение

`app/scoring/explain.py` строит объяснение детерминированно из компонентов:
вердикт, сильные стороны (≥ 55), слабые (< 55), пропущенные данные.

LLM получает готовый объект и только переформулирует его человеческим языком.
Если модель недоступна, ответ содержит `generated_by: "engine"` и тот же
детерминированный текст — функциональность не теряется.
